# Historian OS SKYNET — pamięć projektu

## Cel

Historian OS SKYNET ma pełnić funkcję trwałej, wersjonowanej pamięci projektu: przechowywać nie tylko dane historyczne, ale również dorobek pracy, ustalenia, źródła, relacje, materiały i elementy oczekujące na dalsze opracowanie.

## Zasada ciągłości

Nie odtwarzamy projektu od zera przy każdej sesji. Nowe ustalenia powinny być dopisywane do istniejących rekordów lub tworzyć nowe rekordy połączone relacjami.

## Dotychczasowy kierunek prac

- budowa zewnętrznej pamięci dla Historian OS SKYNET,
- rozdzielenie danych, schematów, indeksów i konfiguracji,
- rekordy kanoniczne z jednoznacznymi identyfikatorami `HOS-*`,
- relacje krzyżowe zamiast duplikowania informacji,
- walidacja struktury rekordów przez GitHub Actions,
- rozwój korpusu LOTNICTWO jako pierwszego rzeczywistego korpusu.

## Udokumentowane rekordy pierwszego etapu

- `HOS-LOTNICTWO-000001` — Jan Zumbach
- `HOS-LOTNICTWO-000002` — Dęblin / Szkoła Orląt
- `HOS-LOTNICTWO-000003` — Dywizjon 303
- `HOS-LOTNICTWO-000004` — Stanisław Skalski
- `HOS-LOTNICTWO-000005` — Wacław Urbanowicz
- `HOS-LOTNICTWO-000006` — Zdzisław Horbaczewski

## Ważne ustalenie

Rekordy robocze nie są automatycznie uznawane za fakty zweryfikowane. Status `draft` lub `review` pozostaje do czasu uzupełnienia i sprawdzenia źródeł.

## Dalsza odbudowa

Należy odzyskiwać wcześniejszy dorobek tematycznie i zapisywać go w Historianie jako rekordy, źródła, relacje oraz wpisy pamięci projektu. Nie należy zastępować istniejącego dorobku nową, równoległą strukturą.
