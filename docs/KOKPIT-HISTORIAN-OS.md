# HISTORIAN OS SKYNET — KOKPIT

## Cel

Jedno środowisko pracy dla budowy, obsługi i archiwizacji Historian OS SKYNET.

## Role aplikacji

| Narzędzie | Rola | Zasada |
|---|---|---|
| ChatGPT | Orkiestracja i główna warstwa zapytań | Planowanie, analiza, relacje, praca z repozytorium |
| GitHub | Magazyn źródłowy | Trwałe rekordy, indeksy, kod, historia zmian |
| Claude | Druga opinia / kontrola jakości | Porównywanie analiz i wykrywanie luk |
| Gemini | Narzędzia Google / dodatkowe wyszukiwanie | Materiały i usługi ekosystemu Google |
| Meta AI | Pomocnicza warstwa AI | Alternatywna analiza i szybkie zadania |
| Obsidian | Lokalna mapa wiedzy | Notatki robocze, połączenia i szkice |
| Termux | Warstwa wykonawcza | Skrypty, walidacja, import/export, automatyzacja |
| F-Droid | Zaplecze open-source | Narzędzia pomocnicze i instalacje open-source |

## Hierarchia źródeł

1. GitHub — wersja trwała i kanoniczna.
2. Zweryfikowane źródła historyczne — podstawa treści rekordów.
3. Obsidian — materiał roboczy.
4. Modele AI — analiza, porządkowanie i propozycje; nie zastępują źródeł.

## Przepływ pracy

`materiał → analiza → rekord → indeks → relacje → weryfikacja → GitHub`

## Zasada bezpieczeństwa danych

Żadna ważna informacja nie jest uznawana za zachowaną tylko dlatego, że wystąpiła w rozmowie. Rekord uznajemy za zachowany dopiero po zapisaniu go w repozytorium i podpięciu do właściwych indeksów.

## Dla archiwum F1

`MOTORSPORT → FORMUŁA 1 → kierowcy / zespoły / konstruktorzy / samochody / tory / sezony / wyścigi / wypadki / memorial`

Każdy element ma własny rekord i może być połączony relacjami krzyżowymi.
